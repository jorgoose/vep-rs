# vep-core

The data model of vep-rs, a Rust reimplementation of the Ensembl Variant Effect Predictor (VEP): the variant, transcript, consequence and coordinate types every other crate reads and writes, plus the shared structural-variant, codon and prediction-matrix rules. All eight sibling crates depend on it: `vep-io` builds an `InputVariant` from each input line, `vep-effects` fills it with `TranscriptConsequence` rows, and `vep-cli`, `vep-builtins` and `vep-plugin` read and extend those rows. The crate writes no files; its product is the in-memory record the writers print.

Throughout this README "Ensembl VEP" is the reference implementation, `ensemblorg/ensembl-vep` release 116.2, the engine the [root README](../../README.md) measures vep-rs against.

## How it works

Take the VCF (Variant Call Format) line `chr21 25000100 . ACG A . . .`, a two-base deletion. The VCF reader in `vep-cli` hands the `POS` text to `coordinate::parse_pos`, which accepts any spelling that names an exact integer, the way Perl numifies the column (`3e7` is a position, `30425949.5` is not), and the `INFO` text to a `vcf_info::InfoFields` view, split once by its first lookup, whose `value("SVTYPE")` is the last `SVTYPE` as Perl's hash would hold it. `sv_routing::written_alts` splits the `ALT` column as Perl's `split` does, and `sv_routing::routes_to_structural` answers whether the line is a structural record; here `REF` and `ALT` are plain `ACGT` runs, so the reader trims the shared `A`, computes the one-based inclusive span and calls `InputVariant::new`, which normalises `chr21` to `21` through `coordinate::normalize_chromosome`, keeps `chr21` in `original_chr` for output, builds the allele string `CG/-` and classifies the pair as `VariantClass::Deletion` through `classify_variant`. The variant then reaches `vep-effects`, which reads each overlapping `Transcript` (exons, introns, the coordinate mapper and translateable sequence of its `TranscriptVEFC`, loaded by `vep-cli` from the cache), takes the per-transcript facts from `Transcript::facts()` once per transcript, translates reference and alternate codons through `codon::translate_codon_with_table` under the transcript's codon table, and pushes one `TranscriptConsequence` per transcript into `transcript_consequences`, each carrying a `ConsequenceList` of Sequence Ontology (SO) terms whose `rank()` and `impact()` follow Ensembl Variation's table. Plugins add `plugin_data` entries to the variant or to a consequence row. The writers finish the record through `location()`, `uploaded_variation()`, `display_allele()` and `Consequence::so_term()`. Had the `ALT` been the symbolic `<DEL>`, `routes_to_structural` would have sent the line to `sv_record::structural_variants`, which gives the record one SO term and class through `sv_routing::sv_type_abbreviation` and `sv_so_term_and_class`, spans each allele from `POS` + 1 through `sv_span::structural_start` and `structural_end` and builds a breakpoint record's own breakend and its mates; a `<CNV:TR>` record read with a reference sequence to hand is expanded first by `sv_record::tandem_repeat_allele_string` into the explicit alleles of a sequence record.

## Modules

| Module           | Role                                                                                                                                                                                                                  |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `lib.rs`         | Module list and the workspace constants: the Ensembl VEP release the binary reports, the default upstream and downstream distance, buffer size and cache region size                                                   |
| `allele.rs`      | Shared-prefix and suffix trimming to VEP-style minimised alleles (`"-"` for an empty side), transition versus transversion classification, IUPAC (International Union of Pure and Applied Chemistry) ambiguity codes |
| `assembly.rs`    | `Assembly`, the reference genome parsed leniently from `--assembly` (`GRCh37`, `hg19` and `37` are one value) with its Ensembl and UCSC (University of California, Santa Cruz) names                                 |
| `cache_info.rs`  | `CacheInfo`, the metadata a cache directory's `info.txt` or `info.json` carries: species, assembly, version, prediction availability, variation columns, the `regulatory` marker, source versions, contig order       |
| `codon.rs`       | Standard-code codon translation with the vertebrate mitochondrial table's four exceptions, complement and reverse complement, three-letter amino acid names                                                            |
| `consequence.rs` | The 41 SO consequence terms with rank, impact, accession and text; `TranscriptConsequence`, the row the effects engine produces, with `FeatureType` (whose order is the order a record's rows print in) and `MotifFields`, a motif row's matrix fields; `LofteeContext`, the transcript structure a consequence-filtering plugin reads |
| `coordinate.rs`  | `Strand`, `GenomicPosition`, `GenomicRange`, the coordinate ceiling `MAX_COORD`, Perl-faithful `POS` parsing and `normalize_chromosome`                                                                                |
| `minimal.rs`     | `--minimal` over one record's alleles: `trim_sequences`, the minimisation of a bi-allelic record and the per-allele split of a multi-allelic one, as Ensembl VEP minimises in its parser and its input buffer                        |
| `prediction.rs`  | Decoder for the gzip-compressed SIFT (Sorting Intolerant From Tolerant) and PolyPhen prediction matrices embedded in the cache, and the Perl-style formatting of a score                                               |
| `so_ontology.rs` | The `is_a` ancestry of the 41 consequence terms within the Sequence Ontology, 57 terms with their accessions and direct parents, whose `descendants` the `is_child` filter operator reads                           |
| `spdi.rs`        | `spdi_genomic`, one allele's SPDI notation as Ensembl VEP writes it, and `ga4gh_vrs_from_spdi`, the GA4GH VRS (Variation Representation Specification) allele derived from it, for the `--spdi` and `--ga4gh_vrs` columns |
| `sv_record.rs`   | `structural_variants`, which turns one structural VCF record into the variants it writes rows for: class, span, breakends and mates, tandem-repeat expansion, allele numbering                                        |
| `sv_routing.rs`  | Whether a line is structural, how its `ALT` list is read, the type abbreviation Ensembl VEP derives from the joined ALTs and the SO term and class that abbreviation names                                               |
| `sv_span.rs`     | The start and end of a symbolic record from `POS`, `SVLEN` and `END` under the breakpoint, tandem and general rules, with the errors under which Ensembl VEP skips the record                                                |
| `synonyms.rs`    | `ChromosomeSynonyms`, the chromosome synonym table of a `chr_synonyms.txt` or `--synonyms` file (whitespace-split lines, the first token the reference name and every later token a synonym of it, both ways) and the name a source holds a chromosome under, as Ensembl VEP's `get_source_chr_name` resolves it |
| `terms.rs`       | `Vocabulary`, the `--terms` choice (`SO`, `display` or `NCBI`) of the name a consequence prints under, each label falling back to the SO term                                                                        |
| `transcript.rs`  | `Transcript` and its parts: `Exon`, `Intron`, `Translation`, `TranscriptVEFC`, the cDNA-to-genome `ExonCoordMapper`, protein features, prediction matrices, and the lazily computed per-transcript facts and ordinals |
| `variant.rs`     | `InputVariant`, one allele of one input record with its annotation results; `VariantClass` and its SO term; `ColocatedVariant`; the output helpers that print a variant as Ensembl VEP names it                         |
| `variation.rs`   | `CachedVariation`, one known variant from the variation cache: name, alleles, minor allele frequency, clinical significance, population frequencies                                                                   |
| `vcf_info.rs`    | `INFO` column lookups that reproduce the hash Ensembl VEP's parser builds: the last occurrence wins, a bare key is a flag, keys match exactly                                                                            |

## Public API

The items a caller reaches for, by module. The record types (`InputVariant`, `TranscriptConsequence`, `Transcript`, `CachedVariation`, `CacheInfo`) derive `serde::Serialize` and `serde::Deserialize`, and `InputVariant` and `TranscriptConsequence` are the JSON (JavaScript Object Notation) documents a dynamic-library plugin receives ([docs/developers/writing-a-plugin.md](../../docs/developers/writing-a-plugin.md#what-run-receives)).

| Item                                                             | Module        | What it gives a caller                                                                                                                                   |
| ---------------------------------------------------------------- | ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `InputVariant`                                                   | `variant`     | One allele of one input record: coordinates, alleles, class, `transcript_consequences` (transcript, regulatory and motif rows alike), `intergenic_overlap` (the allele overlaps no transcript and keeps its intergenic row beside its regulatory rows), `colocated_variants`, `plugin_data`, the structural-variant fields |
| `InputVariant::new`, `InputVariant::without_allele`              | `variant`     | Build a variant from a chromosome, span and allele pair; build the no-allele record of a non-variant line (`ALT` `.`) over its reference                     |
| `location`, `uploaded_variation`, `variation_name`, `display_allele` | `variant` | The Location, `Uploaded_variation`, JSON `id` and Allele columns as Ensembl VEP prints them                                                                |
| `first_vcf_id`, `id_names_record`                                | `variant`     | A VCF record's name as Ensembl VEP's parser stores it (the first `;`-joined ID, `.` and `0` kept, an empty field or element none) and whether a stored name names its record in `Uploaded_variation` and as a mate stand-in (Perl-true and not `.`) |
| `VariantClass`, `classify_variant`                               | `variant`     | The sequence and structural classes with `so_term()`, `is_structural()` and `is_span_type()`                                                              |
| `ColocatedVariant`, `MatchedAllele`, `colocated_in_output_order` | `variant`     | A known variant co-located with the input record, the input and record alleles it matched (`applies_to_allele` gates a row), and Ensembl VEP's report order |
| `Consequence`, `ConsequenceList`, `Impact`                       | `consequence` | The 41 terms with `rank()`, `impact()`, `so_term()`, `so_accession()`, `from_so_term()` and `most_severe()`; `Ord` follows rank                          |
| `TranscriptConsequence`, `FeatureType`, `MotifFields`            | `consequence` | One row of annotation against a transcript, regulatory feature or motif feature, with `feature_overlap()` for the structural-variant overlap columns; `FeatureType`'s `Ord` is the order a record's rows print in (transcript, regulatory, motif); `MotifFields` carries a sequence variant's motif row's `MOTIF_NAME`, `MOTIF_POS` and `TRANSCRIPTION_FACTORS` |
| `LofteeContext`                                                  | `consequence` | Exons, introns, coding bounds and `cds_*_NF` flags attached to a row only when a consequence-filtering plugin is active                                    |
| `Transcript`, `TranscriptVEFC`, `ExonCoordMapper`                | `transcript`  | The cached transcript model; `facts()` and `feature_ordinals()` compute once per transcript and are shared by every row against it                        |
| `PredictionMatrix::lookup`, `decode_prediction`, `format_prediction` | `transcript`, `prediction` | A SIFT or PolyPhen prediction for a protein position and amino acid, printed as Perl prints the score (`0.01`, not `0.010`)              |
| `Strand`, `GenomicRange`, `parse_pos`, `normalize_chromosome`    | `coordinate`  | Strand as `1` or `-1`, one-based inclusive ranges, `POS` as Perl numifies it, `chr21` to `21` and `chrM` to `MT`                                            |
| `translate_codon_with_table`, `reverse_complement`               | `codon`       | Amino acid for a codon under the standard or mitochondrial table; strand conversion of a sequence                                                          |
| `trim_alleles`, `classify_ts_tv`, `ambiguity_code`               | `allele`      | Minimised alleles with the bases trimmed from the start; transition or transversion; the IUPAC code for a base set                                        |
| `Assembly::parse`                                                | `assembly`    | `Grch37` or `Grch38` from any common spelling, `None` for anything else                                                                                    |
| `structural_variants`, `tandem_repeat_allele_string`, `parse_ci_field` | `sv_record` | The variants of one structural record and a `<CNV:TR>` record's allele string over its reference run, each read from the record's `InfoFields`; a `CIPOS` or `CIEND` pair |
| `trim_sequences`, `minimise_bi_allelic`, `apply_minimal_split`   | `minimal`     | Ensembl VEP's `--minimal`: the two-sided trim of one allele pair with its span, the bi-allelic record's minimisation and the split of a multi-allelic record whose alleles trim |
| `routes_to_structural`, `written_alts`, `sv_type_string`, `sv_type_abbreviation`, `sv_so_term_and_class`, `perl_true` | `sv_routing` | The structural-path decision, the `ALT` list as Perl reads it, the record's type string, its abbreviation and SO term, and Perl's string truth (`""` and `0` are false, every other string is true), applied to an `SVTYPE` value and to a Perl-style plugin switch such as LoFTEE's `run_splice_predictions` |
| `structural_start`, `structural_end`, `SpanClass`, `SpanError`   | `sv_span`     | A symbolic record's span and the reason Ensembl VEP would skip it                                                                                           |
| `InfoFields`, `info_field`, `info_value`, `info_value_written`   | `vcf_info`    | One record's `INFO` column, split once and read by every lookup, and single-key scans of it: a key as Perl's hash holds it, flag, written value or absent |
| `CacheInfo`, `CachedVariation`, `ChromosomeSynonyms`             | `cache_info`, `variation`, `synonyms` | Cache metadata, a known variant from the variation cache, a chromosome name map                                                   |

The full item list with doc comments is the rustdoc, built below.

## Run it

The crate follows the workspace's standard commands ([the contributing guide](../../CONTRIBUTING.md)). Scoped to this crate:

```bash
cargo build -p vep-core
cargo test -p vep-core
cargo doc --no-deps -p vep-core
```

`cargo test -p vep-core` runs the modules' unit tests and `tests/prediction_fixtures.rs`, which decodes two prediction matrices taken from Ensembl's public variation database and checks their per-category counts and sampled cells against the packing rule of Ensembl's `ProteinFunctionPredictionMatrix.pm`.
