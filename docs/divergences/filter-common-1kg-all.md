# `--filter_common` and `--freq_pop 1KG_ALL` read the 1000 Genomes `AF` column

A difference in which records and alleles are written, under flags no measured dataset is run with; nothing is set aside, and a run under them is charged to vep-rs in both figures.

Ensembl VEP's frequency filter reads the population `--freq_pop` names from each co-located variant's cache record (`AnnotationSource/Cache/BaseCacheVariation.pm`, `get_frequency_data`, lines 179-256). `1KG_ALL` is the default population and the one `--filter_common` sets (`Config.pm` lines 319-322 and 442-446). For it the filter reads the record's `minor_allele` and `minor_allele_freq` (lines 215-230) and, without them, the record's `1KG_ALL` or `ALL` keys (line 232). A release-116 cache carries none of these: its 1000 Genomes frequencies are the `AF`, `AFR`, `AMR`, `EAS`, `EUR` and `SAS` columns of its `variation_cols` line.

Under `1KG_ALL` no variant has frequency data, so `--filter_common` keeps every record and prints no `FREQS`, and `--freq_filter include` under that population drops every record. On the input of `tests/golden/116/GRCh38-freqfilter` against the release-116 GRCh38 cache, Ensembl VEP 116.2 writes the same records with the same values under `--check_existing --filter_common` as under `--check_existing`. The default output is byte-identical, the tab and VCF outputs differ by the empty `FREQS` column `--check_frequency` adds, and the JSON objects are equal. The corpus's `provenance.json` records the comparison.

vep-rs resolves `1KG_ALL` to the cache's `AF` column, the 1000 Genomes combined-population frequency `--af` reports. So `--filter_common` drops the alleles whose 1000 Genomes frequency is 0.01 or more, and `FREQS` names the population as given (`1KG_ALL:C:0.006789`). Every other population reads the same column in both engines. The `GRCh38-freqfilter` corpus runs the explicit form, `--check_frequency --freq_pop AF --freq_freq 0.01 --freq_gt_lt gt --freq_filter exclude`, under which the two engines filter alike.

On a cache whose `variation_cols` declare `minor_allele` and `minor_allele_freq` (the fabricated slice of `tests/golden/116/GRCh38-minor-allele-columns`), Ensembl VEP 116.2 filters under `1KG_ALL` by `minor_allele_freq` and fills the one remaining allele with one minus it, while vep-rs still reads `AF`. That corpus runs no frequency filter, so the difference is stated here and compared nowhere.
