# `--regulatory`, and `--everything` through it, write no regulatory rows

A difference in which rows a record gets, under flags no measured dataset is run with; nothing is set aside in the concordance figures, and a run under them is charged to vep-rs in both.

Ensembl VEP's `--regulatory` annotates every record against the regulatory features and transcription-factor binding motifs of its cache (`AnnotationSource/Cache/RegFeat.pm`, read from the `_reg.gz` files beside the transcript files). A record inside a regulatory feature gets a `RegulatoryFeature` row: `regulatory_region_variant`, with `regulatory_region_ablation` or `regulatory_region_amplification` for a structural variant covering the feature. A record inside a motif gets a `MotifFeature` row (`TF_binding_site_variant`, with `TFBS_ablation` or `TFBS_amplification` likewise) carrying `MOTIF_NAME`, `MOTIF_POS`, `HIGH_INF_POS`, `MOTIF_SCORE_CHANGE` and `TRANSCRIPTION_FACTORS`. A record overlapping no transcript keeps its `intergenic_variant` row beside them. `--everything` switches `--regulatory` on (`Config.pm` line 362).

vep-rs reads no regulatory cache. Under `--regulatory` it writes the `BIOTYPE` column and the five motif columns empty on every row, the six fields of Ensembl VEP's regulatory group, and no `RegulatoryFeature` or `MotifFeature` row. It writes one warnings-file line saying so and produces every other column of `--everything` as Ensembl VEP does. A record Ensembl VEP annotates against a regulatory feature alone is its `intergenic_variant` row in both engines, and that record's JSON `most_severe_consequence` is `intergenic_variant` where Ensembl VEP writes the regulatory term.

When the FASTA names a chromosome unlike the cache, such a record's intergenic row under `--spdi` names it as the cache does in Ensembl VEP and as the FASTA does here, `21:30234968:A:G` against `chr21:30234968:A:G`. The regulatory feature hands the variant its slice there (`AnnotationType/RegFeat.pm` line 126), a slice vep-rs never has.

The `GRCh38-everything` golden corpus compares the two engines under `--everything` with the mask class `regulatory_feature_rows`, which the test runner and `scripts/concordance/compare_vep_formats.py --masks` both apply. The reference's `RegulatoryFeature` and `MotifFeature` rows are set aside, and the `most_severe_consequence` of each JSON record that lost such a row is recomputed from the rows that remain. The notice vep-rs writes to its warnings file about the exclusion is required and set aside, and every other row and field compares exactly.
